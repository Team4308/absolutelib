Trajectory Solver

The TrajectorySolver module calculates the optimal shooting pitch, flywheel RPM, and required exit velocity based on the robot's physical constraints and projectile motion physics.

Shooter System Data Flow

The calculation sequence is managed by ShooterSystem. First, we select the calculation source based on the active ShotMode. If the primary method fails, we fallback to our known safe states. Finally, adjustments for robot movement, RPM deficits, and safety limits are applied.

Physics and Environment Configuration

AbsoluteLib models trajectories with optional air resistance and obstacle avoidance. Define your specific Game Piece parameters to yield highly accurate physics results.

// Example: Initialize Solver
TrajectorySolver solver = TrajectorySolver.builder()
    .gamePiece(GamePieces.REBUILT_2026_BALL)
    .config(SolverConfig.defaults())
    .build();

// Define Shot
ShotInput input = ShotInput.builder()
    .shooterPositionMeters(1.0, 2.0, 0.5)
    .shooterYawDegrees(45)
    .targetPositionMeters(5.0, 5.0, 2.5)
    .shotPreference(ShotInput.ShotPreference.HIGH_CLEARANCE)
    .robotVelocity(vxMps, vyMps, omegaRadPs, 0.25)
    .build();

// Evaluate
TrajectoryResult result = solver.solve(input);
if (result.isSuccess()) {
    System.out.println("Pitch: " + result.getPitchAngleDegrees());
    System.out.println("RPM: " + result.getRecommendedRpm());
}

Running with a Coprocessor (Recommended)

The Trajectory Solver uses a high-fidelity RK4 physics simulation. While it can run on the roboRIO, the mathematical intensity means you must trade off accuracy for CPU budget by using SolverConfig.roboRIO() or limiting the number of iterations.

For the best performance and highest accuracy, it is highly recommended to run the trajectory system on a dedicated coprocessor (like an Orange Pi, Raspberry Pi, or Jetson). AbsoluteLib includes a specialized coprocessor module designed specifically for this use-case.

How to use the Coprocessor Module:

  • High Fidelity Solving: The coprocessor can comfortably run SolverConfig.coProcessor() which provides sub-millimeter integration timesteps and precise 3D obstacle avoidance checks without dropping loop times.
  • Networked Requests: The coprocessor module includes a TrajectoryWrapper that listens for TrajectoryRequest packets from the roboRIO over UDP/TCP.
  • Prediction Loop: The coprocessor can recursively simulate the future position of the robot using the current velocity and time-of-flight to perfectly compensate for system latency and movement.
  • Setup: Ensure you pass your `robotOmegaRadPerSec` (angular velocity) to the ShotInput builder from your swerve odometry so the coprocessor can apply tangential physics drift correctly!
